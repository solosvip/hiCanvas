# 文字排版由画板自己算，浏览器和本机服务结果逐位相同，画面按算出的行显示

文字的宽度、换行和高度决定外框。编辑器在本地副本上预览，本机服务再按同样的命令算一遍并保存（ADR 0009）；AI 经 MCP 排版也在本机服务这一侧算。两边差一点，松手时文字就会跳。所以排版不交给浏览器：一个纯几何的排版模块在浏览器和 Node 里用同一份数据，算出逐位相同的宽度和行。

- 字宽：画板自带的四套字体随应用分发，两端用 fontkit 读同一份字体文件，按字体自带的连字和字距规则计算。
- 系统后备字：中日韩字和表情由 macOS 系统字体显示。不打包中文字体；按字符类用一组校准常量（在运行中的浏览器里量得，例如常用汉字、全角标点、假名每字一个字号宽），加相邻标点的修正。没校准过的字按固定规则估算，并在排版结果里标出来。应用启动时在浏览器里复核几项校准值，对不上就记警告。
- 换行：UAX #14 断行规则，字素切分用固定版本的纯 JS 实现（运行时自带的 Intl.Segmenter 随 Node 和 Chromium 版本变化）；规则按旧版文字的计算样式。
- 连续全角标点不挤压（text-spacing-trim: space-all）。旧版默认会把「。」」这类相邻全角标点挤掉半个字宽，但挤不挤取决于行尾位置，静态规则复现不了，会让约 5% 的样本换行和浏览器不同。这是与旧版的有意差异，记在功能清单里待用户验收。
- 画面按算出的每一行显示，行内不让浏览器再换行，画面和保存的外框天然一致。编辑文字时仍用富文本编辑器自己的排版，第二轮样本中约 0.2% 的行和松手后的显示不同；松手后以算出的行为准。

例外：画框标题使用 system-ui 系统字体，由浏览器测量自然宽并缓存，只在标题文字变化时重测。它是固定屏幕字号的界面装饰，测量只影响显示和截断，不进画板数据，也不进服务端几何；以后若要将标题宽度用于保存或命令，必须先修改本 ADR。以后由交互层支持点中标题以选中或拖动画框时，标题宽度由宿主注入测量函数，交互层不读 DOM；没有窗口的服务端和 MCP 不提供标题点中。本单不实现这一交互。标题与正文均显式关闭标点挤压。

代价：多三个运行时依赖，许可随包保留；系统字体的校准值跟 macOS 的字体版本绑定，系统升级要复核；以后扩展语言或换行规则时，两端一起改、一起测。

## Considered Options

- 浏览器量，把结果写进记录：本机服务和 MCP 新建文字时没有浏览器，只能等打开画板再补量，会在用户没有操作时产生写入。
- 两端用 HarfBuzz 的 WASM 版：精度与 fontkit 相同，还要多带一套 TTF 和 WASM。
- 构建时生成字宽表、运行时查表：处理不了连字和组合音标。
- 打包思源黑体、思源宋体：中文字的样子会变，体积 32 MB 以上；校准常量已经让常用中文的误差为 0。
- 保留旧版的标点挤压：要按行尾上下文重新整形，没有可靠的静态规则。
