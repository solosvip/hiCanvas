# 生成网页使用独立本机来源，控制与导出经实例消息通道

画板中的生成网页、影片与幻灯片会执行用户或第三方脚本。继承的同源 srcdoc 同时允许脚本和 same-origin，能读取父窗口与存储、借父身份调用本机接口；播放、DOM 编辑、截图和影片导出又直接依赖子页 DOM。合成 Chromium 原型中，opaque srcdoc 的现有截图组合失败，独立来源子页运行同一 helper 则可返回正确像素。因此采用独立 loopback 内容宿主，每次挂载使用不复用的随机主机名，与画板、其他实例不同源。

内容宿主只发布当前文档已授权的有限资源，不提供画板 API、任意文件或通用代理。响应保留 sandbox，桌面保留既有 Node／IPC 边界；父服务的来源检查不为内容页放宽，可信来源的生成 HTML 和 SVG 直接导航也返回不授父来源的响应级 sandbox。第三方公网脚本仍可运行，不通过禁网代替身份隔离。端口由系统在运行时分配，从本机启动信息取得，不写入画板或 connection.json。

父子最终经每次加载新建的 MessagePort 通讯：握手绑定窗口、精确来源、版本与实例；命令有白名单、schema、编号、超时、取消、大小与频率限制。播放、媒体、素材等待和 DOM 操作在子页内部完成；帧就绪后传像素，音轨传有界 PCM，父页验证数据并负责编码、下载与合成。导航或销毁废弃旧通道，不提供执行父代码、任意 fetch、保存画板或调用 MCP 的命令。

保存格式、HTML 原文、资源 URL、CowartFilm 和 MCP 协议不变；映射与桥只在运行时存在。DOM 编辑保存仍由父宿主走编辑命令和版本保护。离线播放器不得依赖运行中的内容服务，需单独验收资源和消息机制。迁移依次为 #112 内容宿主、#113 通道与播放、#114 截图、#115 影片导出、#116 就地编辑、#117 Slides／Play.html、#118 收口。各阶段开关默认关闭，关闭保留原加载路径；#112 只接加载，不能据此宣称已有播放、编辑和导出适配，最终收口才删除旧路径。

代价是增加有界宿主，并将同步 DOM 调用改成异步能力接口，需验证第三方资源、音视频、离线与桌面兼容。收益是浏览器与桌面共用安全和导出边界，保存格式不变。隔离不保证恶意内容返回值真实，也不代替资源配额或进程沙箱。

## Considered Options

- opaque srcdoc／blob：来源隔离强，但现有 html2canvas 克隆路径实测失败，作为统一路径需更换或深改截图方案；只需翻页消息的离线播放器可另用。
- 共享内容来源：隔开父 DOM，却让内容实例互读；不同端口也不隔开同域 cookie。每实例主机名避免另建共同信任域。
- Electron 自定义协议／独立 session：可加桌面边界，但浏览器仍需另一实现，本轮沿用 ADR0002 的薄外壳与共用服务。
- 父窗口开放 DOM／通用 fetch 代理：把父权限给回子页，否决，只提供明确消息命令。
