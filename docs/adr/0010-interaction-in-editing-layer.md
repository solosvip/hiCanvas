# 画布交互由编辑层的工具状态机处理，选中等会话状态不写进画板

选择、拖动、缩放手柄、框选、创建形状这些画布里的交互，全部放在编辑层：每种工具一个状态机，登记在一张工具表里，产品界面只决定开放哪些工具。窗口事件由界面层的画布外壳翻译成与窗口无关的输入（指针按下、移动、松开、取消，按键，滚轮，带屏幕坐标、按键修饰和笔压），交给编辑层；编辑层不碰任何窗口对象，可以在没有窗口的测试里逐帧驱动。

一次手势对应工作副本上的一次手势（ADR 0009）：按下时开始，移动时预览命令，松开时整次提交，Esc 取消；所以一次拖动只产生一个事务、一次撤销。

选中了什么、鼠标悬停在哪、当前工具、正在编辑文字的形状、框选范围、吸附线、视角，这些**会话状态**只放在编辑层的状态原子里：不写进画板记录、不提交给本机服务、不进撤销历史。每个窗口各有一份；视角照旧另存为画板的视角文件。

选择框、手柄、框选矩形、吸附线这些**覆盖层**，由编辑层按会话状态算出一份纯数据描述（画布坐标），渲染层照描述画在形状之上，样式取设计令牌。手柄的点中也由编辑层按同一份描述计算，不靠网页元素命中。指针移动时的点中查询走纯几何入口，配一份按记录更新的空间索引，不在每次移动时取整份画板快照。

代价：界面层必须把窗口事件转交编辑层，不能直接在形状上挂事件；别的窗口和 AI 看不到这个窗口选中了什么，需要告诉 AI 的目标要在请求里写明；覆盖层的外观要通过渲染层的覆盖层描述扩展，不能在界面里随手画。

## Considered Options

- 交互写在界面层的组件里：每个产品要重做一遍拖动和手柄手感，违反「交互手感各产品共用」，也没法在无窗口测试里验证。
- 选中写进画板的会话记录（旧版就把它和画板放在一起）：每次点选都会产生提交和广播，撤销历史里混进选择变化，两个窗口还会互相抢选择。
- 渲染层自己处理指针和手柄：渲染层就得知道选择和编辑规则，违反「渲染层只画」，换渲染实现时交互也得重写。
