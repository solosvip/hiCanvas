# 渲染层内部用 React 画形状，对外只给与框架无关的挂载接口

渲染层的网页元素（DOM/SVG）实现，内部用 React 19 加 MIT 的 `@tldraw/state-react`：每种形状一个组件，按记录订阅，只重画变化了的形状。对外只暴露与框架无关的接口：把画布挂到一个页面元素上、设置相机、查询某个位置下的形状、卸载。调用方不需要会用 React，编辑层也不依赖 React。选它的理由：tldraw 本身就是这样画的，按 #36 的实测，5000 个元素仍可用；从 Cowart 继承的网页、影片、幻灯片形状本来就是 React 组件，可以搬过来改写；hiCanvas 的默认界面也是 React。代价：用别的界面框架的产品，渲染层内部也会带上 React；以后若要换成不依赖框架的画法，需要重写各形状组件，但挂载接口不变，调用方不受影响。

## Considered Options

- 不用框架，直接创建和更新 DOM，按记录订阅：没有框架依赖，但每种形状都要手写创建与更新代码，Cowart 的形状组件要全部重写，工作量大、容易出错；目前也没有实测数据说明性能上需要这样做。
- 让各产品界面直接用渲染层的 React 组件拼出画布：接入最省事，但这样 React 就成了渲染层公开契约的一部分，换了界面框架的产品没法用。
