# 确认类编辑用相关记录作前置条件，由本机服务在保存锁内裁决

状态：已采纳。依据 #231 审定，接入新编辑底座的确认类编辑；正式 Cowart 界面尚未切换。

用户正在输入图片描述、对象链接或嵌入网址时，AI可能在画板其它位置插入结果。这些无关变更不应打断确认。目标自身、祖先或相关资源变化时，仍必须拒绝旧草稿覆盖新内容。仅在窗口里比较目标不足以保证这一点：请求送达前，服务端可能又收到其它写入。

确认类编辑携带可选的 `recordBasis`，表示用户开始操作时相关文档记录的完整值及操作所需的关系集合；`expectedRevision`仍必填。编辑层先复核原意，在实际发送时使用当前已确认版本；本机服务在现有画板保存锁内，再根据实际语义命令推导依赖并核对基线完整性、当前记录值和关系集合。通过后在当前服务端快照执行命令、保留原来的校验与原子保存顺序，记一次本操作者历史，并广播实际保存结果。相关性与比较规则由编辑层的公开纯接口共用，不能让服务端信任调用者自选的空ID列表。

基线只存在于会话与请求中，不写入画板或撤销历史，不建立旧快照缓存。按记录ID去重和结构相等比较，祖先先比较完整记录。命令只更改一个属性，也不能覆盖远端对同一个对象其它属性的修改。涉及容器自动整理或共享资源清理时，依赖还包含成员集合，防止遗漏晚到的新成员。新建对象的ID与层序按当前服务端状态生成；页面里新增其它无关对象不会仅因排序而成为冲突。

本单支持新建网址形状、网址形状互转、图片描述和对象链接。图片描述的确认从可重放的手势路径改为一次离散命令。拖动等连续手势沿用原规则；复制粘贴、媒体导入和拍平接入由后续工单扩展同一接口，不在本单提前实现。带基线的未知命令、不完整基线或超限请求明确拒绝。

一次确认只发一次修改请求。409或保存结果不确定时，只刷新并报告，不带新版本重发；保留能保留的草稿，由用户决定后续动作。相机、焦点、选择、组字、工具和销毁等会话检查继续由原入口处理，不进入文档基线。

带记录条件的成功回执必须包含实际保存快照，不能仅用本次变化推算整板：最后一刻放行的无关远端记录可能尚未到达窗口。缺少快照按不确定结果处理，只刷新、不重发。带记录条件的正式 operations 回执保留命令 results，供创建嵌入的入口取得服务端生成的对象编号；没有条件的旧回执继续省略 results，广播格式不变。

不带 `recordBasis` 的既有调用继续严格比较整板版本，不把旧客户端默认为可以跨版本覆盖。撤销、重做、旧整板快照PUT、删除画板保持各自契约。因此尚未接入前置条件的旧客户端仍可能遇到无关写入导致的409。

代价：请求需要携带相关记录基线，占用额外字节；前置条件与命令合计遵守现有请求预算，超限明确拒绝。成员条件统一建立索引，不能让条件数量倍增保存锁内的整板扫描。语义命令增加读取依赖时必须同步更新唯一依赖收集入口及反例回归。完整祖先比较可能保守地多报冲突，待实际读数证明必要后再收窄比较字段。

## Considered Options

- 只在编辑层比较相关记录，服务端保留整板版本检查：窗口已收到的无关写入可以放行，提交途中的无关写入仍造成409，不能满足本单场景。
- 遇到409就刷新版本并重发：确认可能已经保存而回执丢失，容易产生重复插入/历史；也可能把旧草稿写回已变目标。
- 删除服务端版本检查、不验证依赖覆盖：不完整的客户端基线会静默遗漏祖先、资源或关系变更，不能保证不覆盖别人。
- 保存旧版本快照或引入协同数据结构：扩大持久化与恢复协议，新增缓存寿命、重启一致性或整套合并规则；本单的相关记录前置条件无需这些状态。
- 使用摘要替代完整记录：可以减少传输，但需要额外的规范化和摘要协议；本版先选择两端直接比较完整记录及明确预算，不引入弱散列。
