# 替换 tldraw 的受限部分，沿用其 MIT 数据层

tldraw 的编辑器引擎、默认形状与界面、图标素材使用受限许可，不能用于正式产品，而 hiCanvas 要成为以后多个产品共用的画板底座，因此决定用自己的实现逐步替换这些部分。tldraw 的数据层（store、tlschema、state、utils、validate）是 MIT 许可，存档格式、记录结构和版本迁移都在其中，所以沿用它而不另造一套中立格式：旧画板无需转换，MCP 协议不变，换底层的风险集中在编辑和渲染。代价是数据结构保持 tldraw 的形状；为此锁定其 5.1.1 版本，需要改动时复制进仓库自行维护。

## Considered Options

- 继续使用 tldraw 并购买商业许可：每个产品都受其授权条款约束，不符合做自有底座的目标。
- 另造中立文档格式并迁移旧数据：在许可上没有额外收益，却要承担全量数据转换和协议兼容的风险。
