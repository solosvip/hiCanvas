# 新编辑器在窗口里改本地副本，手势结束才提交，由本机服务裁决

新编辑器在窗口里持有一份画板的活存储（MIT 数据层的 Store）。拖动、缩放、改文字这些交互，用编辑层同一套命令直接作用在这份存储上，画面立刻跟着变。一次手势结束（松开鼠标、确认输入）时，才把这次的净变化作为一个事务提交给本机服务。本机服务是唯一的裁决者：核对版本，用编辑层再校验一遍，记下操作者和撤销历史，保存后把实际保存的结果广播给所有窗口和 AI；编辑器收到后以服务端的结果为准。如果提交时服务端版本已经变了（比如 AI 刚写过），编辑器先收下别人的改动，再把自己这次的改动重新放上去；只有两边碰了同一批记录才算冲突，这时放弃本地这一次改动并提示用户，不覆盖别人的。撤销历史放在本机服务里，界面和 AI 用同一个撤销入口，按操作者区分（ADR 0007）。

代价：拖动过程中，别的窗口和 AI 只看到松手后的结果，看不到中间状态；发生冲突时，用户这一次手势白做，但不会丢别人的工作。

## Considered Options

- 每一帧都提交给本机服务：本机往返虽然快，但每秒几十次保存会拖慢存储，撤销历史也会被一次拖动塞满。
- 改用协同编辑数据结构自动合并：要换掉现有的版本号和存档格式，多一套依赖；两边同时改同一个形状时谁生效，用户也难以预料。
- 撤销历史放在窗口里：关掉窗口就丢失；窗口也看不全 AI 的改动，判断冲突还要另外同步一套信息。
