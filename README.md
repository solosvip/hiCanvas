# hiCanvas

基于 [Cowart](https://github.com/zhongerxin/Cowart) 逐步建设的独立 AI 画板。

## 现在能做什么

这一版提供独立本机画板、自定义生图/改图模型，以及通用 MCP。用户可以手动画图、输入文字、拖入图片、添加标注；也可以让 Rex 等支持 stdio MCP 的客户端操作画板。画板在浏览器中显示，本机服务负责保存。

左上菜单栏可以新建、重命名和切换对话。每个对话的画板、页面、图片结果和视角独立；模型配置共用。多个 Agent 可以操作不同对话；同一对话的并发修改采用版本检查，旧版本会被拒绝，需要读取最新内容后合并。

画板内置文本模型和聊天助手属于下一阶段。保留的 AI 网页、影片、幻灯片按钮尚未接通内置文本模型；MCP 可批量创建普通形状、页面和 HTML embed，但完整 PPT/影片生成及导出尚未提供。

## 安装与运行

使用 Node.js **24** 和 npm。先检查 `node --version`，复用已有 Node 24；无需安装新的运行时。

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run build
npm start
```

在浏览器打开 **http://127.0.0.1:43218/**。保持终端服务运行，按 Ctrl+C 停止。只监听本机，不开放局域网。端口占用时会明确退出，不会悄悄换端口；需要换端口可运行 `HICANVAS_PORT=43219 npm start`。

开发时用 `npm run dev`；修改本机服务后需要重启，预览时修改源码还需重新构建。

本机已有 Homebrew Node 24、但默认 Node 是其他版本时，可以先在当前终端运行：

```sh
export PATH="/opt/homebrew/opt/node@24/bin:$PATH"
```

## 画板保存在哪里

默认在 `~/Documents/hiCanvas/canvas/`。对话索引在 `conversations/index.json`，各对话的 `state.json` 一起保存画板文档与版本；图片、选择项、视角也归各自对话。保存锁由 Node 24 内置 SQLite 管理，进程异常退出后自动释放，不需安装数据库；画板内容仍保存在 JSON。备份时复制整个 `canvas/` 文件夹。

旧 Cowart 画板在首次打开“我的画板”时读入新的对话格式，原页面及图片文件保持不变；之后以新的对话快照为准，旧文件不会跟着继续更新。回退旧版代码只能读到导入前的旧画板，回退前先备份新对话资料夹。不要同时用旧版和新版编辑同一份资料。

源码与画板分开保存。要使用其他位置，在启动服务时指定：

```sh
HICANVAS_PROJECT_DIR="/你的资料目录" npm start
```

也可用 `HICANVAS_CANVAS_DIR` 直接指定画板目录；两者同时设置时，后者优先。浏览器的 URL 带有对话 ID，不跟随另一个窗口的对话切换。刷新和重开会恢复该对话；没有指定 URL 时恢复上次打开的对话。

自动保存有短暂延迟，关闭服务或刷新前稍等片刻。无法读取或保存时会显示错误；部分记录损坏时停止加载并保留原文件；保存失败会持续显示“尚未保存”，恢复服务后自动重试，也可点击“重试保存”。遇到文件损坏请先备份整个资料夹，不要用空画板覆盖。

## 添加自己的生图模型

点击画板左上菜单栏的设置图标→“添加模型”，自行填写显示名称、接口格式、API 基础地址、模型名和密钥，可以保存多组并随时切换、修改或删除。没有预设的服务地址、账号或模型名单。保存设置不会发送生图请求。

目前支持两种接口格式：

- **OpenAI Images 兼容**：基础地址包含服务商要求的版本路径（通常 `/v1`），自动追加 `/images/generations`；有参考图时使用 multipart `/images/edits`。支持返回 base64 图片或可直接下载的图片 URL。
- **Gemini generateContent**：基础地址包含版本路径（通常 `/v1beta`），自动追加 `/models/你填写的模型名:generateContent`，支持文字与参考图输入及内联图片输出。

具体模型由用户填写；兼容这些格式的网关也可接入。仅提供聊天、Responses、异步任务或其他自有格式的服务需要另做适配，不是任意图片 API 都能直接使用。模型需要同时具备相应生图/改图能力；尺寸、质量等参数当前采用服务的默认值，图片框比例作为提示词传递。远程地址使用 HTTPS，本机无鉴权接口可用 HTTP 并留空密钥。

添加后选择“AI 图片”创建图片框，选择模型、写描述，按“生成”；可以上传或粘贴 PNG、JPEG、WebP 参考图。对已有图片添加箭头和文字标注，再按“按标注修改”，使用当前模型在旁边生成新图，保留原图。

生成结果先保存到本机，随后放入原页面并自动保存；菜单栏的“图片结果”可以找回本对话最近 40 张结果、下载或放入当前页。请求不会自动重试；网络中断或超时可能已经计费，请先检查服务商记录后再手动重试。

设置默认保存在 `~/Documents/hiCanvas/settings/image-models.json`，跟随 `HICANVAS_PROJECT_DIR`；可用 `HICANVAS_SETTINGS_DIR` 单独指定。密钥以本机文件权限保护（文件 `600`），浏览器读取配置只返回“已保存”状态，不回显密钥；本机磁盘上的配置是明文，备份时请自行保管。编辑密钥留空保留旧值，更换地址或接口格式须重填密钥或明确勾选清除。生成图片保存在各对话的 `assets/` 中；旧画板仍引用原资源目录。

## 接入 Rex 或其他 MCP 客户端

先按上文安装依赖并构建，再在客户端的 MCP 配置中添加以下 stdio 服务（把路径换成实际项目目录；macOS 已有 Node 24 可直接使用下面的绝对路径）：

```json
{
  "mcpServers": {
    "hiCanvas": {
      "command": "/opt/homebrew/opt/node@24/bin/node",
      "args": ["/Users/solos/Documents/myproject/hiCanvas/bin/hicanvas-mcp.mjs"]
    }
  }
}
```

MCP 会连接本机服务；没有服务时自动启动已经构建的画板，最后一个 MCP 客户端退出后画板服务仍保留。默认 `http://127.0.0.1:43218`，可用 `HICANVAS_URL` 指定另一个本机端口。发现端口是旧版服务或其他资料目录时会明确报错，不会停止它；请先关闭旧服务，再重新连接。不要在多个端口同时编辑同一份资料目录。

Agent 的使用顺序：

1. 首次调用 `open_conversation`，可以直接创建对话；无需在画板里先手动新建。记录返回的 `conversationId`。
2. 后续所有读写传同一个 ID。普通重复调用 `open_conversation` 会复用当前绑定；只有用户要求另起对话才设置 `createNew: true`。
3. 要跨客户端重启恢复，传原 ID，或将外部聊天自己的稳定标识作为 `bindingKey`。也可在该 MCP 进程的环境变量里设置 `HICANVAS_CONVERSATION_KEY`。**不要给所有外部聊天设置同一个键**，否则它们会共用同一画板。同一聊天的子 Agent 应共享已有 ID。MCP 无法自动得知所有客户端的聊天标识；未提供 ID/稳定键时，保证范围仅为当前 MCP 连接。
4. `get_canvas` 读取快照、页面、选择项和 `revision`；`apply_canvas_operations` 携带该版本原子批量新增、修改或删除。发生 `revision-conflict` 后重读并合并，不能直接重放整份旧快照。
5. `list_image_models` 读取配置的模型名单；`generate_image` 使用其中的模型生成或参考图改图，并按比例插入目标页、保留原图。失败不自动重试。若图片已生成但插入冲突，用 `list_image_results` 找回，再插入已有资源；不要重复生成。`read_image` 可让支持图片工具结果的客户端查看本对话图片。
6. 调用 `open_canvas`（或首次打开时传 `openWindow: true`）会打开浏览器中的指定对话。浏览器里切换其他对话不会改变 Agent 的 ID。

MCP 不提供密钥的读取与修改工具。画板通过本机 HTTP 复用同一套保存和生图逻辑，MCP 客户端不直接写文件。

## 检查

```sh
npm run check
```

统一入口运行数据/API 回归测试、设计规范检查、生成令牌一致性检查、继承样式之外的颜色/尺寸检查、生产构建和资源路径检查，以及源码行数、文档位置、规则入口和私人文件检查。数据测试使用自动清理的临时目录和本机模拟生图服务，不调用真实供应商。包括真实 HTTP 的对话隔离、恢复、损坏保护、版本冲突，以及 MCP stdio 协议、重复绑定和生图冲突找回。设计令牌由 `npm run design:tokens` 重新生成。

本机默认与当前提交比较；检查已提交改动时用 `npm run check -- --base <基点提交>`。CI 使用 PR 的目标提交或推送前的提交。首次克隆后启用提交前检查：

```sh
git config core.hooksPath .githooks
```

提交前跑快检查，CI 跑完整入口。仓库为公开仓库，GitHub Actions 使用云端 Ubuntu 检查机运行完整入口。本地检查通过后仍需核对 PR 的远程检查结果。

本次浏览器验证使用合成图片与文字，实际操作了新建、重命名、切换和刷新恢复对话，确认 MCP 修改与删除页面实时显示；模拟保存断网时切换被阻止、恢复后可继续切换。图片结果独立显示并能放入当前页，其他对话保持空结果；1440 和 390 像素窗口中检查了浮层布局及 Escape 后焦点恢复。浏览器走查尚未接入持续执行的界面守卫；数据、并发、MCP 和保存切换逻辑由回归测试保护。
