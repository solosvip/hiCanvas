# hiCanvas

基于 [Cowart](https://github.com/zhongerxin/Cowart) 逐步建设的独立 AI 画板。

## 现在能做什么

这一版把 Cowart 画板从 Codex 小组件中独立运行出来，保留原有界面：手动画图、输入文字、拖入图片、选择和移动元素、添加标注，以及在本机自动保存和刷新恢复。当前是浏览器中的本机应用，需要本机服务持续运行。

第一阶段接下来再做：自定义生图模型配置，以及让 Rex 等 MCP 客户端的 Agent 操作画板。画板内置文本模型和对话助手放到第二阶段。

**目前没有接入自定义模型或 MCP 服务。** 沿用的 AI 图片、HTML、影片、Slides 按钮及其面板仍在；它们发送请求依赖的模型/宿主尚未接通。多 Agent 同时写入、完整 Slides/影片导出也不作为本版已交付能力。

## 安装与运行

使用 Node.js **24** 和 npm。先检查 `node --version`，复用已有 Node 24；无需安装新的运行时。

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run build
npm start
```

在浏览器打开 **http://127.0.0.1:43218/**。保持终端服务运行，按 Ctrl+C 停止。只监听本机，不开放局域网。端口占用时会明确退出，不会悄悄换端口；需要换端口可运行 `HICANVAS_PORT=43219 npm start`。

开发时用 `npm run dev`；修改本机服务后需要重启，预览时修改源码还需重新构建。

本机已有 Homebrew Node 24、但默认 Node 是其他版本时，可以先在当前终端运行：

```sh
export PATH="/opt/homebrew/opt/node@24/bin:$PATH"
```

## 画板保存在哪里

默认在 `~/Documents/hiCanvas/canvas/`。页面记录和引用的图片放在同一资料夹中，界面、选择状态与视角分别保存；刷新后会恢复已保存内容。移动或备份时复制整个 `canvas/` 文件夹。删除页面会从活动页面索引中移除，旧文件暂不自动清理。

源码与画板分开保存。要使用其他位置，在启动服务时指定：

```sh
HICANVAS_PROJECT_DIR="/你的资料目录" npm start
```

也可用 `HICANVAS_CANVAS_DIR` 直接指定画板目录；两者同时设置时，后者优先。沿用 Cowart 的逐页存储格式。当前仅验证单一浏览器编辑；不要同时开多个窗口编辑同一资料目录。

自动保存有短暂延迟，关闭服务或刷新前稍等片刻。无法读取或保存时会显示错误；部分记录损坏时停止加载并保留原文件；保存失败会持续显示“尚未保存”，恢复服务后自动重试，也可点击“重试保存”。遇到文件损坏请先备份整个资料夹，不要用空画板覆盖。

## 检查

```sh
npm run check
```

统一入口运行数据/API 回归测试、设计规范检查、生成令牌一致性检查、继承样式之外的颜色/尺寸检查、生产构建和资源路径检查，以及源码行数、文档位置、规则入口和私人文件检查。数据测试只使用自动清理的临时目录，不调用生图接口。设计令牌由 `npm run design:tokens` 重新生成。

本机默认与当前提交比较；检查已提交改动时用 `npm run check -- --base <基点提交>`。CI 使用 PR 的目标提交或推送前的提交。首次克隆后启用提交前检查：

```sh
git config core.hooksPath .githooks
```

提交前跑快检查，CI 跑完整入口。仓库为公开仓库，GitHub Actions 使用云端 Ubuntu 检查机运行完整入口。本地检查通过后仍需核对 PR 的远程检查结果。

本次浏览器验证使用合成图片与文字，实际操作创建图形、文字、图片和标注并刷新确认恢复，也检查了窄窗口与图标显示。浏览器检查目前需按上述步骤复验，尚未接入持续执行的界面守卫。
